# ADR-004: Skill canonica `operational-engineering-framework` — il manuale come Claude Code Skill (standard aperto)

**Stato**: Accettato
**Data**: 2026-09-04
**Contesto**: Il manuale viene consumato oggi tramite lettura manuale prevista da `AGENTS.md`/`4_AI_AGENT` §B (Loading Protocol) — un agente deve ricordarsi quale file caricare quando, in prosa. Ricerca 2026 (vedi [BENCHMARK.md](./BENCHMARK.md)): il pattern architetturale corrente per Claude Code è *regole imposte → Hooks · conoscenza contestuale → Skills · confine di delega → Subagents*. Le Skills sono caricate **on-demand** dal modello in base a una descrizione a una riga — esattamente il problema che `4_AI_AGENT` §B risolve oggi a mano.

---

## Contesto

Nei fork che consumano questo manuale (`cyclelab-terminal`, `titan-industrial-forge`) esiste già `.claude/skills/lead-architect-plan/SKILL.md` (nome originale, non ancora rinominato in quei repo), scritta a mano, che wrappa parte del manuale. Verifica diretta fatta in questa sessione:

- Copre solo 3 file su 8 (`1_DESIGN`, `2_EXECUTION`, `4_AI_AGENT`) — non `0_META`, `6_STRATEGY`, `5_BROWNFIELD`, `7_COLLABORATION`, `BENCHMARK`
- Hardcoda `1_DESIGN_FRAMEWORK.md v3.1` nel template — già stale, il manuale è a v3.3
- Contiene riferimenti specifici di progetto (`matassa_core/frozen/`, `docs/LIVE_OPERATIONS_PLAN.md`)
- **Le due copie sono già divergenti** — diff diretto tra i due fork mostra 2 righe diverse (CycleLab hardcoda l'IP policy, Titan l'ha generalizzata)

Inoltre, il formato SKILL.md è diventato uno **standard aperto a dicembre 2025**, supportato non solo da Claude Code ma da Claude.ai, Claude API, OpenAI Codex, Cursor, Gemini CLI, Antigravity, Windsurf — non è più un'ottimizzazione Claude-Code-specifica, il rischio di portabilità considerato inizialmente non si applica più.

## Scelta effettuata

Costruire in questo repo (canonico) una versione generalizzata di `lead-architect-plan`, rinominata `operational-engineering-framework` per allinearla al nome del progetto invece di ereditare il nome legacy specifico del fork CycleLab:
- Copre tutti gli 8 file del manuale, con caricamento a cadenza corretta (sessione per `7_COLLABORATION`, task per gli altri)
- **Nessuna versione hardcodata nel testo** — punta sempre all'header del file target (causa diretta della staleness osservata)
- Nessun riferimento a progetti specifici (stessa regola già seguita nel resto del repo)
- Vive in `.claude/skills/operational-engineering-framework/SKILL.md`, path relativi da root repo

## Alternative scartate

- **Lasciare invariato solo nei fork**: mantiene la divergenza già osservata, nessun beneficio per chi riparte da questo repo canonico
- **Skill monolitica che incolla il contenuto degli 8 file**: contraddice la ragione stessa di usare le Skills (caricamento on-demand) — se tutto è già incollato, tanto vale il vecchio protocollo in prosa
- **8 skill separate, una per file numerato**: valutata, scartata — un agente che deve orchestrare 8 descrizioni per capire quale caricare è più complesso di una skill con un workflow di routing interno, coerente con come `4_AI_AGENT` §A-B già fanno routing in un unico documento

## Pre-Mortem (Pilastro 1, applicato per trattamento CRITICO-equivalente)

- **Scenario**: la skill non viene mai invocata perché la description non fa match con l'intento reale → mitigazione: description con sinonimi/trigger multipli (stesso pattern delle skill già presenti nell'ecosistema, es. `detecting-api-enumeration-attacks`)
- **Scenario**: la skill duplica contenuto degli 8 file e diverge nel tempo → mitigazione: contiene solo riferimenti + workflow di orchestrazione, mai checklist copiate
- **Scenario**: non verificabile in questa sessione che Claude Code la invochi correttamente → **limite dichiarato esplicitamente**, non un falso positivo. Verifica richiesta in una sessione reale successiva
- **Scenario**: i fork non adottano mai la versione canonica, restano divergenti → fuori scope di questa sessione (già segnalato), mitigato solo con un campo "data ultimo confronto" nel file per rendere visibile la deriva quando succede

## Conseguenze e trade-off

**Guadagni**: caricamento nativo on-demand invece di protocollo manuale in prosa, copertura completa 8 file, portabile su più tool grazie allo standard aperto (Claude Code, Cursor, Antigravity, ecc. — il target "AI in generale" dichiarato dall'owner).

**Costi**: nono artefatto da tenere sincronizzato; verifica d'uso reale rimandata a una sessione successiva; i fork restano da migrare separatamente (fuori scope).

## Criterio di falsificazione

Se dopo 2-3 sessioni reali la skill non viene mai auto-invocata quando dovrebbe, o produce falsi positivi (si attiva quando non serve), l'approccio "una skill di routing unica" era sbagliato — rivalutare skill separate per file o abbandonare l'approccio Skills per questo caso d'uso.

## Revisione

Rivedere se: l'adozione reale nei fork rivela che lo scope-8-file è eccessivo (allora tornare allo scope-3-file validato); il formato SKILL.md cambia ancora (verificare via Recency Check, `1_DESIGN` Pilastro 2); la verifica d'uso reale in sessione mostra falsi negativi sistematici.
